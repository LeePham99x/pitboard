---
title: "How account windows keep their data"
sidebarTitle: "Account window data"
description: "Each account window keeps its site's data in a store of its own, which Pitboard never reads and deletes only after your change."
---

Each account window keeps its own store, in WebKit on macOS and in WebView2 on Windows. Linux has no app, and only on macOS can a page shared from a browser reach an account window.

A store holds the site's cookies, storage and caches, sign-in included, in files the system's web engine keeps, as a browser does. On macOS they are under your `~/Library`. On Windows, each store is a WebView2 profile under `%LOCALAPPDATA%\Pitboard App`. [Account windows](/reference/files#account-windows) gives the paths.

## What Pitboard does with a store

Pitboard never reads or copies what a site keeps there, and adds no script to a page. It never signs a window in with a Claude Code or Codex login.

The app records each store and each window's last page in `windows.json`, a file only you can read. It makes a store when the account's window first opens. A renamed account keeps its store.

## When a store is deleted

- Removing a window's website data wipes its store and signs the window out on this computer only.
- Forgetting the account deletes its store at the app's next successful read of the accounts.

The app deletes a store only when its own Pitboard directory recorded it and no other existing one did. A copy run with another Pitboard directory therefore signs no other copy's windows out. While the app cannot read `windows.json`, it deletes no store.

On Windows, WebView2 lets go of a store only once every account window has closed. A store waiting to be deleted opens no window until then, and the menu item that would open it says why. Removing Pitboard in **Settings** > **Apps** > **Installed apps** deletes `%LOCALAPPDATA%\Pitboard App`, and every store with it.

## Links shared from a browser

On macOS, Pitboard's Share extension takes the one web address a browser shares and checks that it is a claude.ai or chatgpt.com page. It hands the address to its app as a [Pitboard link](/reference/account-windows#pitboard-links) and keeps nothing. It is sandboxed, with no network, file or shared-folder access.

On Windows, the share sheet lists only a signed Pitboard, so Pitboard takes no page from it. The installer registers Pitboard links, so a `pitboard://` link opens the app there too.

The app checks a link again and opens nothing until you choose an account. It refuses the sites' sign-in links, since one would sign the window in as whoever it belongs to. [Refused links](/reference/account-windows#refused-links) lists them.
