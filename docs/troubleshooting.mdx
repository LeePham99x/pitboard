## Check first

```sh
pitboard doctor
```

Do not switch accounts while any check shows `✗`, broken. [`doctor`](/reference/maintenance-commands#doctor) lists every check and mark.

`pitboard log` lists the last 20 changes and how each ended; `-n 50` lists 50. In the app, the Pitboard window's **This Mac** pane makes the same checks, and **Activity** shows the log.

[Error and warning codes](/reference/errors) gives the cause and fix of each code a message names. [Fix accounts, usage and renewal](/troubleshooting/accounts), [Fix Claude Desktop accounts](/troubleshooting/claude-desktop), [Recover after a crash, a restore or a change of computer](/troubleshooting/recovery) and [Fix problems in account windows](/troubleshooting/account-windows) cover the rest.

## Claude Code over SSH uses another account

On macOS, a session started over SSH can stay on another account than Pitboard shows, through every switch, and Pitboard warns with `fallback_login`.

A `/login` while the keychain is locked, as over SSH, writes the login to `~/.claude/.credentials.json`, which such a session signs in with. [A login file behind the keychain](/concepts/open-sessions#a-login-file-behind-the-keychain) says what else it does.

1. In a desktop terminal, where the keychain is unlocked, run `pitboard stow`, or click **Put Away** on the app's notice **A login file is left behind the keychain**. A session signed in with the file is signed out.
2. Before you start Claude Code over SSH, run `security unlock-keychain ~/Library/Keychains/login.keychain-db`, or start it from a desktop terminal. Do not run `/login` while the keychain is locked.

When `stow` deletes nothing, its message says why, and [`stow`](/reference/recovery-commands#stow) lists every outcome. If it cannot read the file, make the file readable to you, or delete it, login and all, with `rm ~/.claude/.credentials.json`.

## An account reads `login replaced outside Pitboard`

The only login of the account in use ended outside Pitboard. Pitboard held no copy, so that login is gone, and every read warns with `login_replaced`.

| Tool | What ended it |
| --- | --- |
| Claude Code | A sign-in outside Pitboard, such as `/login`, wrote over it. |
| Codex | A sign-in outside Pitboard, such as `codex login`, wrote over it. |
| Claude Desktop | A sign-in outside Pitboard replaced it, or the account was signed out in Claude, which ends its login at claude.ai. |

[Sign in to the account again](/guides/sign-in-again), or [forget it](/guides/accounts#forget-an-account). Either stops the warning. To add another account without ending the login in use, click **Add Account** in the app, or run `pitboard enroll personal --sign-in`.

## Pitboard changes nothing as root

As root or with `sudo`, Pitboard refuses every change with `elevated`: a file or keychain item made as root would be out of reach of your own runs. A container whose only user is root counts too. `pitboard status` and the status line still answer from the last numbers measured, and write nothing.

Run Pitboard as yourself. [Remove files Pitboard made as root](/install/remove#remove-files-pitboard-made-as-root) cleans up after an earlier Pitboard run as root.

### `SUDO_UID` is set in your own shell

Pitboard takes any run with a non-empty `SUDO_UID` as one under `sudo`. A shell started with `sudo -iu` and your own name passes it on, such as to a tmux server. If `id -un` prints your own name there, run the command without it:

```sh
env -u SUDO_UID pitboard use work
```

To stop it for good, start that shell or tmux again without `sudo`. For the install script, pipe it to `env -u SUDO_UID sh` in place of `sh`.

## Report a problem

Open a [GitHub issue](https://github.com/datlechin/pitboard/issues/new/choose) with:

- What you ran, what it printed and what you expected.
- The output of `pitboard doctor --json`, not plain `pitboard doctor`: it replaces email addresses and account identifiers with digests, and your home with `~`.
- `pitboard --version`, and `claude --version` or `codex --version`.
- How you installed Pitboard, and your macOS or Linux version.
- The last lines of `pitboard log`, if they help. A `reclaim` line can name an account identifier.

For a security problem, follow [Report a vulnerability](https://github.com/datlechin/pitboard/blob/main/SECURITY.md#report-a-vulnerability).
