To open Settings, click Pitboard's item in the menu bar, then choose **Settings** (Command-Comma). It opens on the pane you used last.

## General

| Control | Default |
| --- | --- |
| **Open Pitboard at login** | Off |
| **Menu bar shows** | **Account and usage** |

### Open Pitboard at login

Turned on, it adds Pitboard to macOS's login items. macOS may want your approval first, and Pitboard does not open at login until you give it. The pane then shows **macOS is waiting for you to allow Pitboard in Login Items.** and **Open Login Items Settings**.

If macOS refuses the change, its reason shows under the setting.

### Menu bar shows

| Choice | The item shows |
| --- | --- |
| **Account and usage** | The label of the account in use and its percentage: **work 42%** |
| **Usage only** | The percentage: **42%** |
| **Icon only** | The Pitboard mark |

[Menu bar item](/reference/app#menu-bar-item) says which account and which limit the percentage follows.

## Limits

| Control | Section | Default |
| --- | --- | --- |
| **Switch Claude Code automatically** | **Before an account runs out** | Off |
| **Switch when a limit reaches** | **Before an account runs out** | 95%, from 50% to 99% in steps of 1% |
| **From** | **Warm up limits** | 06:00 |
| **To** | **Warm up limits** | 22:00 |
| A switch for each Claude Code account | **Warm up limits** | Off |

The two switching settings are kept in `app.json`, as [The app](/reference/files#the-app) describes. Both stay dimmed until the app has read that file.

### Switch Claude Code automatically

While the app is open, it switches Claude Code once a limit of the account in use reaches the share. [Switch before an account runs out](/guides/automatic-switching) gives the rules. [`pitboard watch`](/reference/account-commands#watch) never reads this setting.

**Switch when a limit reaches** is dimmed while this setting is off.

The app decides:

- When you turn the setting on or change the share.
- After each usage read.
- After another Pitboard run records a switch or usage.
- At least every 30 seconds.

The note under the section says when running sessions follow, as [Open sessions](/concepts/switching#open-sessions) explains.

While the setting is on, a line under the share says what the app last decided:

| Line | Shown when |
| --- | --- |
| **Watching work: 62% of its 5-hour limit, as of 16:40.** | No limit of `work`, the account in use, reached the share. |
| The same, then **Anthropic holds Pitboard off asking again until 17:40.** | Anthropic told Pitboard to wait. |
| **work has used 97% of its 5-hour limit. Pitboard tries again at 16:41.** | A try at this limit failed a moment ago. |
| **work has used 97% of its 5-hour limit. Pitboard is not switching:**, then the reason | Pitboard holds back. **It decides again at 16:45.** follows while `work` has been in use under 5 minutes. |
| **Pitboard is not switching Claude Code:**, then the reason | Pitboard cannot decide. **It asks again at 16:41.** follows while it cannot identify Claude Code's login. |
| **Pitboard could not switch Claude Code, and tries again at 16:41:**, then the error | A switch failed. |
| **Pitboard cannot tell whether to switch Claude Code:**, then the error | Pitboard could not read its own files. |
| **Switched Claude Code from work to personal: work had used 97% of its 5-hour limit.** | The app switched. |

[When it holds back](/guides/automatic-switching#when-it-holds-back) lists each reason. [Notifications](/reference/app#notifications) lists what the app posts.

### Warm up limits

While the app is open, it warms up each Claude Code account turned on here, between **From** and **To** each day, as [Warm up accounts](/guides/warm-up) describes. `pitboard warm` changes the same setting, and `pitboard watch` reads it.

**To** at 00:00 is the end of the day. A **From** later than **To** runs past midnight.

Each account's row shows where its warm-up stands while it is on. A line under the list says what comes next:

| Line | Shown when |
| --- | --- |
| **Next warm-up: work at 14:50.** | An account is turned on, and this is the soonest it warms up. |
| **Warming up work now.** | That warm-up is due or under way. |
| **The last warm-up came to nothing:**, then the error | A warm-up the app made by itself failed. It shows until the next one starts a period or finds nothing due. |
| Why the setting cannot be read, such as **Which accounts Pitboard warms up, at …, cannot be read** | `warm.json` cannot be read. |
| **Pitboard is not warming up accounts:**, then the reason | Nothing can be warmed up here, for a reason in the second table of [When it holds back](/guides/warm-up#when-it-holds-back). |

## Renewal

| Control | Default |
| --- | --- |
| **Renew parked logins daily** | Off |
| **Renew Now** | A button |

### Renew parked logins daily

Turned on, it has launchd run `pitboard renew` once a day with the command line inside the app. That run renews due parked logins and nothing else. [Keep parked logins alive](/guides/renewal) says why.

Once a Claude Desktop account is enrolled, the note under the setting ends **A parked Claude Desktop login is never renewed.**

The setting is on whenever launchd has the job, including one `pitboard schedule install` made. It then shows **Runs** as **Every day**, and **Scheduled in** with the file that [Renewal schedule](/reference/files#renewal-schedule) names. A change that fails says why under the setting.

You cannot turn it on in three cases. You can always turn it off.

| Case | The pane shows |
| --- | --- |
| macOS runs the app from a temporary copy | Dimmed, with a note that starts **Move Pitboard to your Applications folder first.** |
| The app has no command line inside, as in a build run from Xcode | Dimmed, with **This copy of Pitboard has no command line inside it to run on a schedule.** |
| `PITBOARD_HOME` names a directory other than `~/.pitboard` | A refusal under the setting: the schedule renews only the parked logins in `~/.pitboard`. |

### Renew Now

Renews due parked logins, as `pitboard renew` does, then asks for usage again.

Beside the button, **Renew every parked login that is due.** gives way to the result: the line `pitboard renew` prints, or why Pitboard refused. [`renew`](/reference/maintenance-commands#renew) lists the lines.

## Command Line

**In your terminal** shows the path of the `pitboard` a terminal would run, or **Not installed**. Pitboard looks on your login shell's `PATH`, skipping folders that need your permission, such as `~/Documents`. It then looks in `~/.cargo/bin`, `~/.local/bin`, `/opt/homebrew/bin` and `/usr/local/bin`.

| The `pitboard` found | Note under the row |
| --- | --- |
| The one inside the app, directly or through a link | **The one inside this app, so it updates with the app.** |
| Any other | **Installed apart from this app, so update it the way you installed it.** |

**Install Command Line Tool** shows only when Pitboard finds no `pitboard` and the app's own command line can run. After macOS asks for an administrator's password, it links `/usr/local/bin/pitboard` to `Pitboard.app/Contents/Helpers/pitboard`. It replaces a link already there.

| Case | The pane shows |
| --- | --- |
| macOS runs the app from a temporary copy | No button, and a note that starts **Move Pitboard to your Applications folder first.** |
| A file, not a link, is at `/usr/local/bin/pitboard` | `/usr/local/bin/pitboard` **is already there and is not a link, so it was kept.** |
| You cancel the password prompt | Nothing |
| Any other failure | The reason macOS gives, or **The link could not be made.** |

A note at the foot of the pane points to [`status`](/reference/account-commands#status) for scripts and [`repair`](/reference/recovery-commands#repair).

## Updates

A copy from a release download or the `pitboard-app` cask has these controls:

| Control | Default | What it does |
| --- | --- | --- |
| **Check for updates automatically** | On | Checks GitHub for a newer version once a day. |
| **Download and install updates automatically** | Off | Downloads an update in the background and installs it when Pitboard quits. Dimmed while the daily check is off. |

**Check Now** checks at once, in the updater's own window. Beside it, the pane names your version, such as **Pitboard 0.10.0**. Once a daily check finds a newer one, it reads **Pitboard 0.10.1 is ready to install.** and Pitboard's [Menu](/reference/app#menu) offers **Install Pitboard 0.10.1**. [What leaves your machine](/security#what-leaves-your-machine) lists what the check sends.

A copy built from source has no update key and cannot update itself. Its **Updates** pane shows only **Version** and a note saying so.
